# 设计与修改边界

## 布局与组件

`Dashboard.vue` 负责三组独立数据状态及趋势筛选，页面按累计、今日、趋势、排行组织。`DashboardOverview.vue` 展示历史累计横幅与今日五项，复用四张服务端卡片并追加平均响应；常见桌面宽度五列，窄窗口自然换行且填满行。`DashboardUsageTrend.vue` 接受筛选控件插槽，费用为红色虚线，缓存命中为面积曲线，其余 Token 为细线。`DashboardUsageBreakdown.vue` 以两个排行代替旧成本柱图、环图和默认展开大表，各显示前五项并独立展开。

沿用 Card、颜色变量、字体和 Lucide 图标，减少装饰标签及留白。参考图仅用于层级、密度和缓存曲线，不引入平台拆分或请求日志。所有布局按真实容器宽度检查，不通过裁剪字段掩盖横向溢出。

## 数据来源与统计口径

今日接口显式请求 `/api/dashboard/stats?preset=today` 和本地时区；`system_health.avg_response_time` 已按总耗时 / 响应样本计算，单位秒且包含失败。前端固定两位小数；无请求显示 `--`，缺失或非法数值有独立提示。趋势筛选不能改变顶部指标。

全部累计新增前端方法 `dashboardApi.getLifetimeStats({ timezone, tz_offset_minutes })`，读取现有 daily-stats 从 `1970-01-01` 到本地今天。累计每日请求、Token、原始费用与实际结算，不能再次加 `unattributed_*`。原始记录及保留汇总的去重由已有后端实现保证。只缓存压缩后的累计对象 60 秒，缓存键包含本地日期和时区；非法或负数结果整块失败，不展示部分累计。

不能使用 `/api/admin/usage/stats` 的默认日期窗口冒充全部历史，也不能使用 `tokens.month`：SQLite 存在汇总时后者可能漏掉尚未汇总的原始请求。完整 daily-stats 当前会返回几十年的空日，隔离环境传输约 4–5 MB、耗时小于 100 ms；这是保持仅前端变更所采用的现有接口代价，不把这些空日保留在前端缓存。

趋势复用 `/api/admin/stats/time-series` 与 `/api/dashboard/daily-stats`。前者只含原始明细；`usageTrend.ts` 用后者对齐天 / ISO 周 / 月的保留费用，并在原始请求数不足时把 Token 标为 null。小时视图不分摊每日总量。小时日期虽有 `+00:00` 后缀，已按请求时区转换，展示不再偏移。上游输入 Token 可能包含缓存，明细中解释各项不能直接相加。

模型和提供商排行分别读取同接口的 `model_summary` / `provider_summary` 周期汇总，避免逐日累加已舍入金额导致小额排序错误；按 Token / 费用 / 请求降序，名称作为平局排序。缺失明细单独标注，不创建伪造模型或提供商。金额缺失采用服务端 `unattributed_cost`，避免舍入差额被误标成缺失；费用占比以本组周期费用和保留缺口为分母。业务名称跳过界面翻译，保留原文。累计费用仍受现有每日统计四位小数的接口精度限制。

## 加载与验证

今日、累计、趋势有各自的骨架、空态和失败重试。趋势的两个接口并行加载，一处失败不连带丢弃已成功的排行或顶部数据；筛选变化立即使旧请求失效，再防抖加载最新范围。卸载后不回写页面。

测试覆盖累计完整性与缓存日期、今日秒数与范围、历史明细、失败重试、切换竞态和排行交互。浏览器使用独立 SQLite 与合成数据检查中英文、明暗主题、日期 / 粒度、展开明细及四种窗口尺寸。没有后端改动、真实数据写入或新依赖。
