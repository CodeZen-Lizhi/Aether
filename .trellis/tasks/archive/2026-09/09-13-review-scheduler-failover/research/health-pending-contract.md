# Health Terminal Retry Contract

Approved implementation follow-up for the design terminal-settlement contract. No new service. Storage owns data contracts, memory/SQLite, migration/schema, gateway wrappers; main owns effects, fact serialization and maintenance consumption. Do not change active executor or WS files.

## Repository API

Storage integration handoff: repository methods are `enqueue_key_health_fact(&ProviderCatalogKeyHealthPendingFact)`, `list_key_health_pending_facts(usize)`, `remove_key_health_pending_fact(&ProviderCatalogKeyHealthPendingFact)`, and `key_health_attempt_is_settled(&ProviderCatalogKeyHealthPendingFact)`. GatewayDataState and AppState use the full names below. All four live on ProviderCatalogWriteRepository so receipt reads bypass catalog caches and use the authoritative writer. List returns at most 1024 items, including expired items for explicit diagnostic removal, ordered by original observed time then exact receipt identity. Main owns the effects settlement constructor and must supply the new optional lease deadline; storage updates the probe constructor with None. Cargo remains reserved for integration until explicit coordination succeeds. Channel notification currently fails with EPERM on its workspace-external lock file.

Add `ProviderCatalogKeyHealthPendingFact` with `attempt_id: String`, `key_id: String`, `api_format: String`, `policy_version: u32`, `attempt_started_at_unix_secs: u64`, `observed_at_unix_secs: u64`, `fact: serde_json::Value`. The opaque JSON is a strict gateway DTO containing no credentials, request headers or model text. Primary identity matches settlement receipts.

- `enqueue_provider_catalog_key_health_fact(&fact) -> Result<ProviderCatalogKeyHealthPendingFact, ...>`: insert once and return the authoritative first fact, immutable on duplicate, reject expired original attempts. SQLite durable; memory mirrors semantics. Does not create a settled receipt.
- `list_provider_catalog_key_health_pending_facts(limit: usize) -> Result<Vec<...>, ...>`: oldest first, bounded. Multiple workers may read the same fact; settlement receipt is the deduplication authority. Expired facts can be removed/returned for diagnostic cleanup; never extend original 24-hour window.
- `remove_provider_catalog_key_health_pending_fact(&identity/fact) -> Result<(), ...>`: idempotent exact identity removal after settled or terminal stale/expired/missing result. No model request is involved.
- `provider_catalog_key_health_attempt_is_settled(&identity/fact) -> Result<bool, ...>`: exact receipt query BEFORE gateway owner/generation prechecks, to recognize an uncertain successful commit whose atomic terminal projection consumed its lease.

Expose matching GatewayDataState and AppState wrappers. Follow existing repository ownership, error conventions and runtime backup exclusions. Add a minimal pending table through existing migration/logical schema and generated baselines, with matching memory state. On SQLite failure pending cannot promise durable acceptance; main will explicitly report retention failure. Do not silently replace durable status with an in-memory success.

The pending table is runtime-only and excluded from portable JSONL/admin backups: restoring an administrative snapshot must not replay unfinished model effects. Existing committed receipt export behavior is unchanged. Full SQLite file reopen retains pending facts. Duplicate enqueue returns the first accepted payload, time and fence under the same write lock/transaction. Callers must settle that returned original. An uncertain enqueue error must not settle the local payload, because a prior immutable fact may already exist. Receipt queries report only unexpired receipts, independently of the supplied fact timestamp; they do not require a key or owner to remain present.

## Atomic Lease Expiry

Add optional `expected_probe_lease_expires_at_unix_secs: Option<u64>` to `ProviderCatalogKeyHealthSettlement` (serde default). For model settlement it is the minimum of active leases from the freshly verified current snapshot. Repositories must compare database/current wall time against this deadline INSIDE the atomic transaction/lock immediately before applying health, after Duplicate detection. If expired return a distinct `ProbeLeaseExpired` terminal result. JSON snapshot CAS already fences lease owner/deadline changes. Probe claim/renew/release operations and non-probe model attempts use None (their own dedicated guards handle their ownership logic). Update all constructors narrowly.

## Gateway Consumption

Main builds immutable fact once at terminal with original fence, typed failure and observed time. Persist the fact before entering retryable state reads/CAS; after Applied/Duplicate remove it. CAS conflicts and storage failures retain it for the existing maintenance runtime to retry. Replay uses the same fence/time/failure, reprojects current health and never sends a model request. Stale credentials/epoch, expired original attempt, missing key or expired/lost probe owner are terminal diagnostics and are removed; a pending fact does NOT authorize revival of an expired probe. Success affinity remains current live-request metadata only; delayed health reconciliation must not mint a new request order or restore stale session binding.
