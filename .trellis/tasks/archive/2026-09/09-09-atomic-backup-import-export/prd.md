# 无版本限制的完整备份

## 需求

- 配置和完整备份按实际数据内容导入，不依赖版本号；新导出不再包含格式版本号。
- 保留已有跳过、覆盖、冲突报错的合并选择。选择确定后，整次导入只有成功或失败，任何实际错误都不允许部分写入。
- 完整备份的配置、渠道凭据、管理员/API Keys、偏好及用量数据必须共同成功或共同回滚。
- 导出任一部分读取、验证或凭据解密失败，整次导出失败，不下载不完整文件。
- 能还原的旧备份按内容兼容。旧文件没有管理员资料时保留目标管理员；空的已退役部分可以忽略，无法还原的非空数据明确失败，不能静默丢弃。

## 验收

- 没有、旧的或任意版本元信息不触发版本门槛。
- 在不同临时 SQLite 实例之间完成真实配置和完整备份的导出、导入、再导出。
- 配置后段和用户后段发生写入失败时，所有前序数据和登录会话保持原状。
- 凭据以目标实例的加密配置重新加密，保持可用性。
- 前端只显示整次成功或整次失败；HTTP 失败不显示成功结果，不生成下载。
- 旧文件缺少提供商/渠道 Key 标识、provider_names 或管理员资料时，依据可验证的内容兼容，不根据版本分支。

## 边界

实现当前管理界面的 JSON 配置/完整备份及其后端链路，不改 CLI JSONL 备份协议、不部署到运行实例、不使用真实用户数据库作写入测试。旧目录清理已单独完成。本次不自动提交或推送。
