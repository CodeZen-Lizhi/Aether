# 设计

## 根因与边界

前后端以固定版本白名单阻止旧备份，当前用户文件还缺少后续新增字段；只删除版本比较不足以兼容。现有导入逐项调用基于 pool 的 repository，每次独立提交，完整导入又顺序运行配置和用户导入；在外层单独开启 SQLx transaction 不能覆盖这些写入。

## 内容契约

- 导出不写 version；导入忽略历史 version 元信息，继续校验对象、数组、字段值、关联关系及凭据。
- 对已知历史字段做显式规范化：缺失 ID 可生成内部源标识；缺失管理员不创建虚假资料；缺失的提供商映射只能根据实际配置及引用确定，歧义时报错。
- 所有实际错误返回失败，取消累积 errors 后继续导入的行为；用户选择的重复项跳过仍作为成功合并语义保留。

## 持久化边界

通过显式的 AdminBackupSession / AdminBackupState 让所有读写使用同一 SQLite 连接。六个参与备份的仓储接受 SqliteConnectionSource：普通调用仍使用原 pool，备份 source 以 Weak 引用指向事务 owner 并串行借用连接；owner 提交、回滚或 Drop 后不能再获取连接。原仓储内的事务在该连接上成为真实 SQLx savepoint，SQL 和 row mapping 只保留一份。运行时的系统配置、用量快照及 totals 则提取连接 helper 复用。配置独立导入和用户独立导入也使用该入口，完整导入只提交一次。事务提前获得写入锁，外键在提交时验证；错误、取消和提交失败由 SQLx 事务回滚。

SQLx 的 COMMIT 已发送后，请求取消不保证数据库未提交，因此最终 commit、应用缓存失效、外部目录 KV 清理及 lease 释放必须同在独立 Tokio 收尾任务中。请求取消只丢弃等待，不终止该任务；在移交收尾前取消则事务 Drop 回滚。外部目录 lease 使用 RAII，覆盖导入阶段的取消释放；包含代理节点变更的备份也参与此协调。

密码恢复和 user_sessions 撤销同属数据库事务。系统配置、授权和调度等派生缓存不能在提交前污染运行实例；事务提交后统一失效。不能用失败后覆盖全库的补偿方案，不能通过遗忘 Transaction 或 task-local 隐式路由实现。

## 导出

先完整读取、解密并验证所有组成部分，再生成响应；前端仅在完整成功响应后创建下载。完整备份内部使用一致数据库快照，避免配置和用户引用跨时点不一致。

## 验证与风险

使用已迁移的临时 SQLite 数据库和真实认证路由。通过后段失败/外键失败检查已写入数据和会话回滚，通过成功往返检查完整性。重型 Rust 编译串行复用产物。测试 fixture 全部合成，不保存真实备份凭据。详见 research/atomic-storage.md 的连接级接入调查。

## 代码边界补充

- 仓储连接适配仅涉及备份使用的六个仓储，保留 pool 的旧构造调用，不修改全局 SqlitePool 别名。
- 提供商 record builder 提取接受目标提供商集合的纯逻辑，常规入口和备份入口共用，避免事务中重新读普通 pool。
- 备份成功同步清理前后台配置/认证/路由缓存和 dashboard 缓存，external selector 的 KV 失效按既有 best-effort 语义处理；缓存清理不在提交后制造数据写入。
- 备份专用 Key 查询包含普通和独立 Key、停用状态及 `is_locked`；普通用户 Key 查询维持原有范围。旧 DTO 的 `is_locked` 默认 false，新导出和恢复 SQL 均保留此认证状态。
- 统计保留全零行、仅实际成本的行和 `is_complete` 原值。字符串列表含损坏成员、非数组形状或未知 API 格式时整体导出失败，不能过滤后继续。
- 已退役的默认用户组 scalar 系统配置原样保存；非空已退役 domain 继续拒绝，不能以清 null 隐去内容。Endpoint 的空重试次数作为继承值保留，不能直接套交互 PATCH 的非空限制。
