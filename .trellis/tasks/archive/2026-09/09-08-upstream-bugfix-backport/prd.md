# 移植适用的上游缺陷修复

## Goal

只移植对个人版现有功能有价值的缺陷修复，保留 `slim-personal` 的裁剪、配置语义、请求诊断和调度行为。

## Background and Authorization

- 比较基线为本地 `58c445ddc` 与上游 `17d01d7fe`。本地工作区开工时干净。
- 用户已在上一轮比较结论后明确授权创建任务并实施第 1、4 类修复；第 3 类 Tunnel 仅在确认必要时处理；明确排除 Gemini。
- 用户的明确、故意改动优先于上游。差异本身不是缺陷，不恢复删掉的功能，不添加新功能，不改变产品意图。
- 初次实施授权不包含提交、push、合并上游或生产部署。
- 2026-09-09，用户后续明确要求“合并回 `slim-personal`”，授权为此提交本任务改动并进行本地合并。
- 用户随后明确要求“提交push”，本任务提交的推送目标为 `origin/slim-personal`。全量上游合并和生产部署仍不在范围内。

## Requirements

- **R1 / Responses 心跳兼容**：上游返回 `type=ping` 时忽略该心跳，不导致协议转换失败，不产生伪正文或提前结束流。保留原有正文、错误和结束事件行为。
- **R2 / 传输错误中的凭据保护**：HTTP、浏览器指纹 HTTP 和 relay 等现有错误诊断在 Display、Debug 和错误链格式化边界不得泄露 URL userinfo、query 或 fragment 中的秘密。保留错误类别、状态、主机/路径等已有排障信息与非敏感原因；不修改原始上游响应体、请求体、数据库捕获策略或调度逻辑。
- **R3 / SOCKS 语义核验**：核对现有 `socks5://` 与 `socks5h://` 在保留的 HTTP/WS 客户端中的实际行为。已有配置明确支持两个 scheme，不能直接移植把所有 `socks5` 自动改成 `socks5h` 的上游策略。只有可复现的现有功能缺陷才修复，否则记录跳过理由并保留契约测试。
- **R4 / Tunnel 条件核验**：说明 Tunnel 与普通 HTTP/SOCKS 手动代理的区别，检查可获得的使用证据和上游补丁依赖。不引入上游新的握手、配置、协议或管理功能；不能证明当前必要性的部分保持不动。

## Acceptance Criteria

- [x] AC1：Responses ping 回归先失败、修复后通过，相关协议转换测试保持通过。
- [x] AC2：凭据 URL 的 Display/Debug/错误链回归先失败、修复后通过；非敏感错误细节与状态保持可读。
- [x] AC3：以隔离本机 mock 验证 SOCKS DNS 行为，确认 HTTP/WS 实际使用配置语义；记录移植或跳过结论。
- [x] AC4：Tunnel 的处理结论有代码、配置或运行信息依据，且未引入新功能。
- [x] AC5：受影响 Rust 包的测试、格式与 lint/type-check 有结论；独立复核确认未改变个人版业务功能、调度、SQLite、界面或 Gemini。
- [x] AC6：任务保留上游来源、验证命令、结果及未采用部分的理由，交付可审阅的本地改动。

## Out of Scope

- Gemini；全量上游合并或 rebase；PostgreSQL/MySQL；用户/钱包/运营模块恢复；新增渠道/管理/协议能力。
- 自动转换代理 scheme、改变代理默认值或改动用户保存的配置。
- 生产请求、真实供应商凭据测试、容器重启或部署。
