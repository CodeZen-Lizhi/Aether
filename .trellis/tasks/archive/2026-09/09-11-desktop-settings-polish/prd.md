# 完善桌面端设置交互

## Goal

提升桌面端设置页的可操作性和视觉比例：桌面应用配置可收起，版本信息展示应用实际版本，代理节点可直接验证连通性，所有弹窗按应用窗口自适应而非过度占满界面。

## Background

- 用户提供的设置页截图显示「桌面应用」配置区域目前始终展开。
- 系统信息当前展示 Git 短提交及 `-dirty` 状态（如 `387d7e56b-dirty`），这不是面向用户的应用版本信息。
- 网络代理节点卡片只有「编辑」入口，无法直接验证代理是否可用。
- 模型管理的新增、编辑弹窗过宽、过高；用户明确要求将此问题作为全局弹窗规则处理。

## Deliverables

1. [`desktop-application-collapse`](../09-11-desktop-application-collapse/prd.md)：使设置页「桌面应用」区域可通过标题栏展开和收起，并保持该区域现有功能可用。
2. [`system-version-information`](../09-11-system-version-information/prd.md)：系统信息展示来自桌面应用发行配置的用户可识别版本，而不展示 Git 工作树状态。
3. [`proxy-connectivity-test`](../09-11-proxy-connectivity-test/prd.md)：在代理节点的快捷操作中提供测试入口；测试应明确反馈成功或失败，编辑流程中也应可触发同一测试能力。
4. [`responsive-dialog-sizing`](../09-11-responsive-dialog-sizing/prd.md)：统一新增、编辑模型及其他应用弹窗的尺寸约束，使其相对窗口自适应、内容可滚动、操作区可达，且不产生横向裁切或溢出。
5. 供应商管理在窄窗口卡片视图中展示已有的余额信息，并复用桌面表格的余额加载、格式化和失败态规则。

## Scope

- 修改桌面端设置和模型管理相关的 Vue 前端、必要时修改其已有 Tauri/本地 API 边界。
- 复用当前项目的 `CardSection`、弹窗组件、i18n 和代理配置约定。
- 对影响范围内的弹窗建立共享尺寸规则，而不是仅修改模型弹窗的单个静态宽高。

## Out Of Scope

- 不改变代理配置对请求流量的作用范围或默认代理保存语义。
- 不改变桌面应用版本发布、构建或自动更新策略。
- 不重构未受本次问题影响的设置页面视觉样式。
- 不处理用户未提及的窗口布局问题。

## Acceptance Criteria

- [ ] AC-1：用户可通过「桌面应用」卡片标题操作展开或收起配置内容；收起后不展示端口、开机启动、目录和诊断日志详情，展开后现有控件仍可操作。
- [ ] AC-2：系统信息展示规范的应用版本号，不包含 Git SHA 或 `dirty` 工作树标记。
- [ ] AC-3：每个代理节点在「编辑」旁提供可见的测试入口；测试进行中有禁用/加载反馈，完成后以清晰的成功或失败提示展示结果。编辑弹窗提供等价测试能力。
- [ ] AC-4：模型新增和编辑弹窗相对桌面窗口具有合理的最大宽高，内容超出时只在内容区域纵向滚动，底部操作可达；在现有其他弹窗中应用相同的共享规则，不依赖单个页面的固定超大尺寸。
- [ ] AC-5：在常见桌面窗口以及窄窗口下，受影响页面和弹窗不出现横向溢出，关键操作（保存、取消、关闭、测试）始终可达。
- [ ] AC-6：供应商管理切换为窄窗口卡片布局时，已配置运营认证的供应商仍展示余额、加载状态或静默失败横杠，不因响应式布局遗漏该信息。

## Constraints

- 新增面向用户的中文文案必须补全英文映射；动态测试结果文案需覆盖字段缺省分支。
- 不覆盖或回退工作区已有未提交改动。
- 测试连接必须沿用项目已有的代理校验或请求边界，避免在前端重复实现不一致的网络逻辑。

## Confirmed Technical Facts

- `frontend/src/desktop/DesktopSettings.vue` 是「桌面应用」区域的实现；当前自定义面板未使用 `CardSection`，诊断日志已采用原生 `details` 折叠。
- `desktop_status` 返回 `version: env!("CARGO_PKG_VERSION")`；桌面端 npm、Tauri 和 Cargo 清单当前一致为 `0.1.7`。系统信息却通过 `/api/admin/system/version` 读取网关构建版本，该接口可能返回 Git 短 SHA 及 `-dirty`。
- 已存在节点测试端点 `POST /api/admin/proxy-nodes/:id/test`，可读取已保存的节点凭据；编辑弹窗已有基于填写值的 `POST /api/admin/proxy-nodes/test-url` 测试。
- 30 个 Vue 组件使用共享 `Dialog`；其 `4xl` 及更大尺寸目前直接映射到 Tailwind 固定上限，模型编辑使用 `4xl`。

## Key Decisions

- 正常桌面设置默认展开，标题栏提供同一位置的收起/展开控制；故障恢复视图保留直接可见的关键控制，避免增加恢复步骤。
- 仅在 Tauri 桌面会话中优先显示 `desktop_status.version`；Web/Docker 保持现有网关版本接口，避免混淆部署版本语义。
- 节点列表测试调用按节点 ID 的既有服务端接口，运行中仅禁用该节点的测试操作，并通过现有 toast 展示格式化的成功或失败结果；不读取、复制或暴露节点密码。
- 共享 `Dialog` 按窗口可用空间约束宽高并维持 header/footer 固定、body 纵向滚动；模型表单同时降至与设置窗口协调的尺寸档，所有采用该组件的弹窗自动获得相同规则。
