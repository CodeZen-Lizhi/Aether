# 窗口自适应布局

## 行为差距与边界

当前 shell 使用固定屏高与多层滚动，表格公共容器默认 overflow-auto；请求表写死最小 1120～1520 px，列宽加总可超过 100%。代码、价格矩阵、时间线也主动使用横向滚动。目标是依据实际容器宽度分配空间、长文本换行、密集内容在窄容器重排，并统一移除可见滚动条。

## 方案

- 公共 shell、PageContainer、标题和工具栏：min-width:0，使用有上下界的间距，消除重复留白。保留可滚动内容和键盘访问。
- 公共 Table：默认铺满容器，列布局可压缩，紧凑内边距和长文本换行。列表容器达到 56rem 才显示表格，请求记录选中超过 9 列时将门槛提高到 80rem，避免金额被拆成难读的多行。列权重按可见列归一化到 100%，与实际 DOM 列顺序一致；卡片保留选中的客户端、IP 和完整 User-Agent。
- 高频页面：核对仪表盘、供应商、模型、密钥、请求记录、路由、系统配置、设置；页面不人为固定内容高度，操作栏可换行。
- 编辑器及详情：代码/JSON/请求头换行，价格配置网格改为可收缩列，时间线节点与重试按钮参与流式布局，序号保留换行后的顺序。请求头对比的左右值共用 grid 行和滚动容器，换行后保持逐行对齐。JSON 视觉缩进最多占内容列 25%；不裁掉超出的业务信息。
- 在全局 CSS 统一滚动条外观策略，处理 scoped 样式的滚动槽占位，纵向滚动行为保留。

## 预计修改范围

frontend/src/style.css，components/layout/ 与 ui/table.vue / table-head.vue / table-cell.vue / table-card.vue / dialog，UsageRecordsTable、Dashboard、ModelManagement、相关 provider / model / request detail 组件，以及桌面入口的间距。仅在实际溢出证据支持时扩展到同一界面范围中的其他组件。

不改变后台 API、统计计算、数据存储、权限或路由行为，不合并另一客户端 UI 分支。

## 验证

使用当前正式网关和临时 SQLite 生成合成数据；Vite 前端只代理隔离网关。测量各尺寸的 scrollWidth/clientWidth 和滚动条样式，核对截图、长内容末尾、表单操作和分页。单元测试覆盖列分配及原有交互。共用修改同步后保持两分支已有客户端差异。
