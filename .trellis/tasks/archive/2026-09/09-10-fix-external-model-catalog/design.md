# 技术设计

## 边界与数据流

```text
models.dev -> 网关有限重试 -> 15 分钟网关缓存 -> 前端 15 分钟缓存 -> 创建预设
                                              \-> 强制刷新成功数据 -> 价格同步
```

后端继续拥有外部网络访问和目录规范化；`frontend/src/api/models-dev.ts` 继续拥有浏览器缓存与扁平模型列表。组件只消费明确的“新鲜成功 / 旧缓存兜底 / 失败”结果，不自行解析 Axios 错误或缓存文档。

## 后端

- 在 `external_cache.rs` 的外部拉取边界增加小规模重试，只覆盖可重试的传输失败与 5xx；4xx、无效 JSON、配置错误等确定性失败不重复请求。
- 使用固定且短的退避，总耗时受现有请求超时与尝试次数约束。
- 最终失败仍由现有目录路由返回 503，保持 API 状态兼容；日志记录尝试次数和脱敏后的错误类别。
- 正常缓存 envelope、代理节点隔离和显式清缓存行为保持不变。

## 前端 API

- 读取浏览器缓存时同时保留“新鲜缓存”和“结构兼容但已过期缓存”的候选。
- 普通目录加载先按现有规则请求新数据；请求失败时才返回旧缓存，并携带 `stale` 状态供 UI 展示。
- `refreshModelsDevList` 使用严格刷新模式：清理缓存后只接受网络成功，不允许回退旧缓存，从而保证价格同步不误用旧价。
- 列表转换逻辑保持单一实现，避免为新鲜和旧缓存各复制一套模型扁平化代码。

## 创建弹窗

- 增加目录加载状态：`idle/loading/ready/stale/error`，把目录错误和空目录分开。
- `stale` 显示缓存提示并允许重试；`error` 显示加载失败和重试按钮；两者都保留“手动填写”。
- 现有模型列表加载失败独立处理，不与外部目录失败互相覆盖。

## 兼容性与风险

- 后端 503 契约不变，现有客户端不受影响。
- 旧浏览器缓存只参与创建预设，不参与价格同步；主要风险是创建预设略旧，但用户仍可编辑，且界面明确提示。
- 自动重试会增加失败请求耗时；通过少量尝试和短退避限制影响。

## 回滚

改动均为读取与展示路径，无数据迁移。可分别回滚后端重试、前端旧缓存兜底和弹窗状态，不影响已存模型。
