# macOS 打包版本自动递增

每次执行桌面 build 分配更高的版本（0.1.0 → 0.1.1 → 0.1.2；末段达到 99 后进位），不再重复 0.1.0。npm 包、Tauri 配置、Cargo 包与对应锁文件同步，应用内版本和升级快照继续读取相同 Cargo 版本。开发启动与单独 prepare 不递增。

范围：新增版本分配脚本及测试，接入现有 desktop.mjs，修改版本元数据和桌面构建文档。分配前验证所有当前版本一致，防止部分文件混用；构建互斥，失败不回退已分配的版本，下一次分配新号。自定义签名配置不能覆盖回旧版本。

只提交、push 当前 codex/tauri-macos 分支，不再向 slim-personal 同步。前序 SLIM 同步已经发生，不撤回既有提交。不修改网关功能、真实客户端数据或另一工作树。

验收：
- [ ] 连续分配得到不同版本，元数据一致，非法/不一致输入不部分更新。
- [ ] 构建锁排斥并行构建并在正常异常退出时释放；现有构建参数与 sidecar 选择保持可用。
- [ ] Node 脚本和相关桌面测试通过，受影响文件检查通过。
- [ ] 当前分支提交并 push；使用已分配的新版本重新打包，实际 Info.plist 两个版本字段、包内资源及安装包校验通过。

本次发布先分配版本并提交，再执行同一资源准备 / Tauri 构建流程，确保安装包来自已提交源码。后续普通 build 自动分配下一版本，不自动执行 Git 操作。仅前端仪表盘部分沿用已通过的 36 项回归与真实浏览器证据。
