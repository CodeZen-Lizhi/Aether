# 优化仪表盘紧凑排版

## Goal

保留仪表盘全部数据与现有视觉风格，重新组织顶部指标、累计摘要和区块间距，降低上半部分占用。

## Requirements

- R1：保留现有全部指标、精度、日期、统计范围和辅助信息。今日五项为请求、Token、费用、全站 RPM / TPM、平均响应；累计包括 Token、请求、费用、实际结算与统计起始日。
- R2：今日概览调整至顶部，统一数值基线、标签与辅助信息层级，缩小字号、图标容器和纵向间距，降低单项指标占用。
- R3：累计数据改为今日概览下方的紧凑横向摘要，减少累计 Token 的过度视觉强调，窄窗口完整换行。
- R4：保留项目字体、颜色变量、明暗主题与既有控件语言。趋势图和排行继续位于概览之后，按需要统一区块间距。
- R5：加载、空数据、独立失败重试、趋势筛选和排行交互继续可用，不因压缩隐藏数据或控件。

## Background

- `frontend/src/views/shared/DashboardOverview.vue:3` 当前累计大卡片位于今日概览之前；累计 Token 使用 30/36px 字号。
- `frontend/src/views/shared/DashboardOverview.vue:133` 今日五项独立卡片具有 32px 图标容器及多层纵向留白，中等宽度排列为两行。
- `frontend/src/views/shared/Dashboard.vue:2` 负责概览、趋势和排行的编排，数据加载和统计范围独立。
- 前端规范 `.trellis/spec/frontend/index.md` 已定义数据口径、主题和响应式约束；本次仅更新其中被排版需求替代的描述。

## Acceptance Criteria

- [x] AC1（R1、R5）：相同数据下，现有全部数值和辅助信息仍可读取；既有仪表盘测试通过，筛选与顶部统计保持独立。
- [x] AC2（R2、R3）：同一数据、同一视口比较改前改后截图和概览高度；在 1280px 和 1920px 宽度，顶部概览目标降低至少 25%，趋势图起始位置明显上移。
- [x] AC3（R3、R4）：840×620、1024px、1280px、1920px 及移动窄屏无水平溢出，长数字和辅助信息完整可读。
- [x] AC4（R4、R5）：真实浏览器检查明暗主题、中英文以及至少一次筛选或失败重试流程；保留证据并明确未验证范围。
- [x] AC5：仅对相关前端文件执行必要 lint、类型检查与仪表盘定向测试，不扩展全仓测试。

## Out of Scope

- 不修改 API、统计计算、数据来源或后端；不新增或删减业务指标。
- 不更换整站主题、字体或图表库，不修改其他管理页面。
- 仅提交并推送本次仪表盘改动到当前工作分支，不发布到生产环境。
