# 全仓遗留功能与性能审查

## Goal

审查 Aether 全仓中产品已删但代码仍保留的功能、前后端可达性断链、过期兼容层和高价值性能问题，输出一份可执行的精简与优化候选清单。先建立证据和删除前置条件，再按独立批次实施修改。

## Background

- Aether 是 Rust workspace 加 Vue 前端的多模块项目，后端主要位于 `apps/aether-gateway/` 与 `crates/`，前端位于 `frontend/`。
- 用户希望确认是否存在“前端已删除但后端仍保留”“功能已不需要但代码、配置、数据库结构仍融合在项目中”的情况，并为后续代码精简与性能优化建立优先级。
- 当前任务只做全仓审查和计划，不修改业务代码、数据库、迁移、公开 API、依赖或部署环境。

## Requirements

### R1. 覆盖功能可达性和遗留代码

- 审查 Rust 后端、Vue 前端、配置、数据库 schema/migration、测试、文档、构建与部署入口。
- 对候选项反查 UI/HTTP/CLI/后台任务/配置开关/测试/文档/迁移引用，不能只凭文件名或单个搜索命中判定为死代码。
- 特别识别前端页面或入口已移除、但后端 handler/service/job/store 仍可达的功能；也识别前端声明已过期、但后端仍是公开契约的情况。

### R2. 区分可删除项与兼容项

- 每个候选项按以下类别归档：真正孤儿、活跃兼容、隐藏/条件可达、迁移/测试/文档专用、需线上或外部客户端确认。
- 每项至少给出证据位置、当前入口/调用链、保留原因、删除风险、前置条件和建议的下一步。
- 不把公开 API、旧数据迁移、企业/部署配置或历史版本升级路径在无证据时误判为可直接删除。

### R3. 识别性能优化候选

- 检查明显的 N+1、无界 fan-out、重复计算、无效 I/O、全量扫描、不必要前端请求和配置/缓存并发安全问题。
- 区分已证实的问题、仅静态推断的候选和需要指标/压测/线上数据验证的项目。
- 为高优先级候选说明建议测量指标、最小改造方向与回滚边界。

### R4. 形成后续实施拆分

- 报告应将低风险清理、共享契约改造、数据库/迁移处理、性能改造拆成可独立验证的后续子任务建议。
- 不在本任务中直接删除任何功能或修改生产行为。

## Acceptance Criteria


- [ ] 审查报告覆盖 Aether 后端、前端、数据库/迁移、配置、测试和文档的主要入口。
- [ ] 每个高信号候选都有文件/行号、可达性判断、分类、风险和删除或优化前置条件。
- [ ] 报告明确区分真正孤儿、活跃兼容、隐藏入口、历史迁移/测试/文档和外部确认项。
- [ ] 至少列出高价值性能候选及其验证方法，不把静态猜测写成已证实的性能结论。
- [ ] 输出建议的后续实现批次及验证方式；本任务不修改业务代码。

## Out of Scope

- 本任务不删除、重命名或重构业务代码，不改数据库 schema、迁移、公开路由、认证行为或依赖版本。
- 不执行会改变外部系统状态的命令，不启动生产服务或写入实际数据库。
- 不根据单一 UI 入口缺失直接删除后端代码；需纳入 API、任务、配置、迁移和外部客户端边界。
