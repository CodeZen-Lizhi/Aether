# 修复外部模型目录加载

## Goal

修复外部模型目录短暂不可用时“同步在线价格”直接报错、创建模型弹窗只显示空列表的问题，让用户能可靠重试或继续手动创建，同时不把旧缓存价格误报为最新在线价格。

## Background

- 两个故障入口共同依赖 `GET /api/admin/models/external`：批量同步会显示后端的 `External models catalog unavailable`，创建弹窗则吞掉同一错误并渲染“暂无可用模型”。
- 网关目录缓存和浏览器缓存都是 15 分钟；缓存未命中时只尝试一次外部请求，失败即返回 503。
- “同步在线价格”通过 `refreshModelsDevList` 先清理前后端缓存，再重新拉取，因此不能依靠现有缓存抵御瞬时失败。
- 2026-09-10 20:57 在本机桌面应用重新触发后，目录接口 1.7 秒返回 200，按钮恢复为“同步在线价格 (0)”。故障具备瞬时性，不是目录结构或价格转换永久损坏。

## Requirements

- R1. 外部目录拉取遇到瞬时传输或服务端失败时，网关执行有限次数、有限时长的自动重试；成功后仍按现有 15 分钟规则缓存。
- R2. 同步在线价格必须基于本次强制刷新成功的数据；所有重试失败后明确报错，不允许用过期缓存静默完成同步。
- R3. 创建模型弹窗的目录加载失败必须与“目录成功但没有模型”区分，提供可见的失败信息、重试入口和现有手动填写入口。
- R4. 创建模型时，如果浏览器保存过结构兼容的最后一次成功目录，在线刷新失败后可以展示该目录作为预设兜底；该兜底不用于“同步在线价格”。
- R5. 保留现有模型价格转换、价格来源选择、模型 CRUD、代理节点选择和 15 分钟新鲜缓存语义。
- R6. 错误日志保留可诊断的失败类别，不记录代理凭据、Token 或完整敏感 URL。

## Acceptance Criteria

- [x] AC1. 后端测试证明：第一次外部拉取失败、后续重试成功时，目录读取返回数据而不是 503。
- [x] AC2. 后端测试证明：达到最大重试次数后及时返回不可用，不出现无限等待。
- [x] AC3. 前端测试证明：创建弹窗在线加载失败但存在兼容旧缓存时仍展示模型预设，并明确这是缓存结果。
- [x] AC4. 前端测试证明：创建弹窗在线加载失败且无缓存时展示“加载失败”、重试按钮和“手动填写”，而不是“暂无可用模型”。
- [x] AC5. 前端测试证明：“同步在线价格”刷新失败时不会应用旧缓存价格。
- [x] AC6. 现有模型预填、在线价格同步和批量同步相关测试保持通过。
- [x] AC7. 前端类型检查和构建通过；Rust 格式检查及受影响后端测试在可用工具链中通过。

## Out of Scope

- 不修改 models.dev 的数据格式、定价换算或计费引擎。
- 不新增定时价格同步、数据库持久化目录或内置静态模型清单。
- 不调整代理节点 CRUD、系统代理策略或模型管理页面布局。
- 不提交、发布或覆盖当前 Tauri 任务的其他改动。

## Technical Notes

- 当前可重复的人工反馈路径为：桌面应用 `/admin/models` -> “同步在线价格” -> `GET /api/admin/models/external` 的状态及按钮结果。
- 本机 Rust 工具链当前未出现在 shell `PATH`；实现阶段优先使用项目可用的 Docker 构建环境或明确记录未能运行的本机 Rust 检查。
