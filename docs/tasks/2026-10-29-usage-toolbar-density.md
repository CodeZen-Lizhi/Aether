# 使用记录标题栏筛选密度调整

日期：2026-10-29

## 目标

- 使用记录页面的状态、传输和调度筛选与时间范围同处桌面标题操作带；三个筛选保持独立边框与间距，不使用共享外框或分段组。
- 类型/状态列头恢复普通列展示，不再重复提供筛选入口。
- 请求类型与传输标签保持带描边和软底的徽章样式。
- 移除标题栏中无明确用途的 unknown 可见性小眼睛。
- 移除筛选区、显示列与自动刷新之间无业务含义的竖向分隔线。

## 实现

- `UsageRecordsTable.vue` 将三维快捷筛选移入标题操作带，与时间范围、显示列和刷新组成同一排；三个筛选各自成控件，窄屏继续自适应展示。
- 删除标题操作带中的三条竖向分隔线，避免在筛选、显示列和刷新按钮之间形成无意义视觉噪声。
- 类型/状态列头改用普通 `TableHead`，类型与传输徽章统一为浅灰描边、软底样式。
- 删除 `hideUnknownRecords` 的前端状态、事件、API 参数和过滤分支，列表始终展示未知模型与提供商记录。

## 验证

- `UsageRecordsTable.spec.ts` 46 项通过；`npm run type-check` 通过。
- 真实组件 fixture 在 1920、1440、1024、900 和 390 像素宽度检查：桌面筛选组与时间范围同处一条操作带，390 像素切换卡片视图，页面及列表无横向溢出。
- 在 1024 像素页面实际操作请求状态筛选为“失败”：请求发送 `request_status=failed`，列表仅保留对应记录；类型/状态列头无筛选按钮，unknown 小眼睛数量为 0。
