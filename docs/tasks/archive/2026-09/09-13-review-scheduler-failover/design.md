# 聊天调度与故障转移技术设计

状态：用户整体批准，实施中。需求权威来源为 [PRD](prd.md)，代码定位与旧结论纠正见 [研究记录](research/failover-plan-review.md)。只改变本轮聊天策略，不新增调度服务。

## 1. 架构与数据流

沿用管理配置/transport snapshot → scheduler 过滤排序 → serving attempt loop → gateway 同步/SSE/WS 执行 → orchestration 终态效果 → 现有仓储与缓存失效。

一次逻辑请求持有模式快照、适用的单调时钟截止时间、逐 K 尝试次数和累计额外等待。排序负责选谁，重试控制负责能否继续，健康负责跨请求可用性；健康未归零不允许绕过次数或时间限制。

扩展现有失败事实，包含规范化原因、归因范围、基础分/直接零、重试资格、Retry-After、attempt ID、凭据/熔断代次和输出提交状态。只分类一次，健康、重试和诊断消费同一结果。保留各协议适配器，不用单一 HTTP 状态替代协议判定。

## 2. 错误分类

识别顺序：排除客户端/网关错误 → 供应商适配的结构化错误码 → 已验证错误模板 → 状态码/传输兜底。只解析错误响应/事件，沿用大小限制和脱敏，不匹配正常模型文本。可信根因可覆盖状态码，例如 500 的明确暂态忙基础扣 1。

| 情况 | 健康 | 重试 |
|---|---|---|
| 429、上游并发满、503/504、首输出等待超时 | 基础 1 + 连续附加 | 有限重试，冷却或预算不允许则备用 |
| 500/502、未知 5xx、可归因上游的连接/DNS/TLS/协议异常、无效成功响应 | 基础 2 + 连续附加 | 条件满足时有限重试 |
| 中转 401/402/403 根因不确定，内部线路鉴权/额度故障 | 基础 2 + 连续附加 | 不凭单次状态判死，不影响调用者鉴权 |
| 可信证据确认当前 K 余额/额度耗尽、凭据不可用 | 直接零并可恢复熔断 | 停止普通尝试，独立请求可备用 |
| OAuth 可刷新到期 | 刷新不作为额外模型失败重复扣分 | 每逻辑请求每凭据代次最多一次受控刷新，真实模型重发占尝试与时间预算 |
| 已交付内容后异常断流/工具调用损坏 | 基础 2；明确等待超时基础 1 | 终止并报告，不透明重放 |
| 参数错误、调用者鉴权失败、客户端取消、本地并发/准入拒绝 | 中性，不扣不回血不清计数 | 按现有请求终止/过滤处理 |
| 未识别 4xx、归因不足 | 不凭空扣分，记录未知 | 按现有协议和用户终止规则，不盲目重试 |

模型不支持按现有能力/兼容范围寻找合法候选，不等同于 K 失效。TLS/网络需区分上游故障和本地证书/代理配置；归因不足只诊断，不能联动扣所有 K。

用户显式终止状态、终止正则、传输终止开关优先保留。健康判定与是否继续分开；成功正则也不能把损坏协议或错误终态认作完整模型成功。

## 3. 尝试配置与等待

内部统一 max_attempts，含首次，范围 1-99；新前后端验证一致，非法值明确报错。次数是上限，不保证一定用完。每次真实模型调用计一次，不能在 transport 和 candidate loop 各自再隐藏重试。

迁移保留原显式优先级：failover_rules → endpoint → provider。先解析旧明确覆盖，再把被 legacy 特判忽略、且没有其他有效覆盖的已保存 2 转为两次；不能简单删除过滤，让 endpoint 的旧默认遮蔽 provider 显式值。无存储值不因 API 展示默认 2 被改写；旧 0 保持一次，新界面禁用重试以一次表达。

在现有配置对象增加策略版本及规范化字段，保留旧字段兼容读取；旧 API 写入经同一规范化入口同步，新旧冲突明确报错。读接口提供 effective_max_attempts 与来源。迁移幂等、支持预览、保留原值，仅限本轮聊天。现有大于 99 的旧配置保留原始值并展示旧实际截断结果，首次编辑要求合法值，避免迁移突然扩大调用次数。

普通暂态错误首次退避随机 0.5-1 秒，后续窗口翻倍、单次上限 2 秒；所需间隔超过同请求同 K 剩余的累计 2 秒预算就跳过，不截短后强行请求。

无有效等待提示的 429/明确上游并发满，共享 K+格式冷却从 1 秒翻倍至 60 秒，完整成功重置阶梯。普通 500 的请求内退避不自动变成全局冷却。有效 Retry-After 优先，标准解析秒数和 HTTP 日期；长值不被本地 60 秒上限截短，异常值诊断后用本地规则。新预算只限制当前请求愿意等多久，不限制上游冷却有效期。

等待不占本地执行并发或长持 K 租约；真实 attempt 前重新检查冷却/健康/本地并发并原子准入。到期冷却已有探测门复用，防止多个请求同时冲入。被跳过、定时器、未执行槽位不计健康。

## 4. 健康与幂等

普通计分失败：第 n 次连续失败额外扣分为 n<=2 时 0、n<=4 时 1、其余 2；健康减基础分及附加分并钳制到零。完整成功加 1 上限 10，连续计数清零；中性事件不变。明确不可用直接零，不为凑满次数继续调用。

保留内部 0..1 归一化存储/API，计算使用定点单位避免浮点残差；用户显示 0..10。旧分数按比例保留，不重置满分，迁移期允许小数。标记策略版本，新严格连续计数从零开始，旧失败预算不能当连续次数。既有熔断和冷却截止时间保留。

同 K+格式按权威结算顺序串行更新，凭据代次和熔断代次隔离旧结果；旧代次结果只诊断，不能清新熔断。K2 成功不能恢复 K1。复用 gateway key 锁和仓储 CAS，但去重必须跨实例，不能只依赖进程内布尔值。

attempt 去重标记和健康/熔断更新在现有数据库同一事务提交，唯一身份含 attempt ID、K、格式、策略代次。优先复用现有终态记录；若其不支持原子契约，扩展现有仓储及 memory/SQLite 实现，增加最小结算结构，不新建服务。去重保留覆盖报告重投窗口，过期报告只能诊断，不能重新扣分。

CAS 冲突重读后重新投影；提交后失效健康相关缓存。低健康、连续计数非零或恢复状态变化时，成功写入节流不得漏掉 +1/清零；满分且无其他变化时可省写。持久化失败保留可重试结算信息并报告，不伪造写入成功，也不因此重发已成功模型请求。

## 5. 熔断与探测

新聊天策略移除旧固定 8 次预算和低成功率窗口的额外熔断触发，窗口只诊断；移除旧 0.25 起步/三次满血恢复。交替轻失败与成功可能保持健康，是容忍暂态故障的预期。

正常 → 零分熔断冷却 → 到期单探测。首次 1 分钟，失败翻倍，现有配置上限约束 1-32 分钟，旧 0 归为最小 1 分钟以避免忙循环。探测完整成功从零恢复 1、连续计数清零；失败保持零进入下一档；中性取消释放租约，不加罚或升级间隔。

租约需覆盖/续期到真实终态，不能固定 60 秒过期后让未结束的探测与第二个重叠；丢租约不能写成功恢复，取消/进程退出有回收。每个排队 attempt 执行前重查，不绕过新熔断。

到期只授予资格，不承诺后台准点探测。仍按模式排序；缓存绑定在备用 K 时不为探测强制破坏亲和。充值/凭据更新可提前允许探测并建立新代次，不未经验证直接满血；本地已知额度/凭据硬过滤须在可信恢复信号后解除。

## 6. 排序和亲和

先满足模型/工具能力与兼容边界。固定模式保留 provider overlay 和 K internal_priority；未归零的健康变化不改人工顺序，硬过滤/本次失败耗尽仍可转移。

缓存模式暂态失败先保留绑定，冷却/熔断绕过，备用完整成功才迁移本会话。无稳定会话身份沿用现有后备顺序，不跨用户虚构亲和。失效解绑精确匹配 K/格式/目标，不清同 endpoint 其他 K。

成本模式在同等模型/能力/兼容性下先比 default_rate_multiplier，再比同价可用亲和，再按人工优先级和既有稳定兜底。接通真实亲和读取和成功写入，不只修改比较器。模式切换和并发完成要有版本/顺序保护，旧完成不覆盖较新绑定。

复用已有目录 snapshot/cache，同一 K 重试不重复查倍率。不新增实际 token/缓存概率费用预测；存量非法倍率保持现有中性兜底并诊断，新写入严格验证。

## 7. 超时和流式提交边界

90 秒为独立字段（例如 stream_failover_budget_ms），不复用已有 total_ms。通过既有调度配置读写，默认 90000 ms，正整数且沿用现有最大执行时间上限，不设置零值隐式无限。

进入逻辑调度时创建一次单调截止时间，贯穿候选、排队、连接、刷新、退避与首输出门；各阶段取自身超时和剩余总预算较小值。耗尽取消等待、释放许可、不再发新尝试；终态记录有独立有界收尾，不以持久化阻塞继续等上游。

HTTP 头、心跳、response.created、空帧不构成有效模型进展；合法文本、推理/工具调用进展或完整合法终态可以关闭首输出预算。复用有界预提交缓冲，不无限缓存。重放门与首输出门分开：已经向客户端交付某 attempt 的不可重放协议事件，即使还没正文也不能透明转移。工具 ID 和参数片段不得跨 attempt 拼接。

预提交前且可安全重放时才有限转移；已提交后断流明确终止。正常输出后不受首输出预算截断，继续既有流空闲/终态处理，不增加全回答 90 秒限制。普通非流式默认 300 秒、compact 默认 1200 秒及已有覆盖配置保持。

WS 每个独立 response.create 单独预算；握手、首事件、整轮结束和 1 小时连接限制各自保留。只有已证实可重放且未交付不可重放内容的独立轮次才换 K，上游部分写入/执行状态不明不假定安全。带 previous_response_id 等引用的续接依原 K/物理绑定，失败不删引用、不跨 K、不重建历史。HTTP 同类引用也核对，不能只验证 WS。

全局预算耗尽与客户端取消不重复当作 K 的独立上游超时；已有确定失败结算一次，未尝试候选不扣分。请求级记录预算耗尽，避免隐藏慢请求。成功回血须等完整正常终态。

## 8. 配置、展示和回退

沿用分组保存契约，保留条件、阶段、请求修改和终止规则。只修改必要配置/状态展示，不增加策略页面或大改 UI。显示权威生效次数、调度健康与恢复状态；现有 health-monitor-utils 的成功率不能重命名为健康分。

详情记录分类、基础/附加分、健康前后、连续次数、尝试序号、跳过原因、时间预算和恢复时间。列表遵守简洁展示规范，错误详情脱敏，不暴露密钥和模型正文。保存/刷新读取同一权威状态。

配置/健康均标策略版本，所有执行者完成兼容升级后才启用；不能旧新健康算法混写。迁移预览列出变化目标、保留原值或快照。回退停止新写入后恢复匹配版本配置/健康，不能直接旧二进制混读新状态；去重证据不随回退删除。发布/生产迁移需另有明确授权。

验证按 PRD A1-A11，具体计划见 implement.md。当前无修改后测试通过结论，旧未取得最终输出的 cargo 命令不算证据。真实 Codex 自动恢复、中转错误模板覆盖和时延应分别注明已验证范围。
