# 聊天模型调度与故障转移优化

## 状态与授权

业务讨论已收敛，用户在整体审阅后明确回复“实施”，本版及技术默认值已获实施授权，任务进入 in_progress。不提交、发布或调用付费上游。

交付：[技术设计](design.md)、[实施与验收计划](implement.md)、[代码事实与讨论记录](research/failover-plan-review.md)。研究记录中的早期建议由本版 PRD 和设计取代，不是额外需求。

## 目标与范围

让三种调度模式在聊天、开发场景的真实请求中按预期选择、重试和转移，容忍中转站的偶发故障，并限制等待。主场景为 Codex APP 开发及其他聊天。

覆盖聊天 HTTP 同步、SSE 和 Responses WebSocket 的适用执行路径，以及配置读写、健康状态、冷却、熔断恢复、亲和和诊断。实际客户端传输与上游时延未经实测，不能把 HTTP 测试当作 WS 验证。

不增加第四种模式或独立的故障转移模式选项；不做图片、视频、embedding 的新增重试，不做并行竞速、实际费用预测、跨供应商历史重建。共享模块和已有非聊天行为需保持兼容。

## 已确认需求

| 编号 | 契约 |
|---|---|
| R1 | fixed_order 按人工供应商和 K 优先级；健康分不得隐性将其改成动态负载均衡。 |
| R2 | cache_affinity 优先复用同供应商、同 K，服务长开发任务的缓存需求。 |
| R3 | cost_based 优先便宜的 K，失败后仍按本模式寻找候选，具体成本口径见 R22。 |
| R4 | 产品上只有现有三种完整模式；内部可分开候选排序、重试、健康、熔断职责。 |
| R5 | 本次请求可以在健康未归零时切换 K；本次绕过和后续持续排除是不同动作。 |
| R6 | 当前 K 按生效配置有限尝试，不为耗尽健康无限重试。“2 次”指首次加一次重试。 |
| R7 | 禁用、已知不可用、未到恢复条件的熔断、模型不匹配、本地 K 并发满等调用前过滤，不扣健康。 |
| R8 | 上游并发满/限流与本地满不同；前者可有限重试并扣当前 K 的分，不自动伤及其他 K 或整个供应商。 |
| R9 | 健康用户视角为 0 到 10，作用域为同 K、同接口格式；K2 成功不恢复 K1。 |
| R10 | 普通失败扣错误基础分加连续附加分：429/上游并发满、503/504、首输出等待超时基础 1；500/502、可归因上游的连接/TLS/协议异常及不确定中转鉴权错误基础 2；可信根因优先于状态码。不设基础 3 分档。 |
| R11 | 连续计分失败第 1-2 次附加 0，第 3-4 次附加 1，第 5 次起附加 2；错误类型变化不重置计数。 |
| R12 | 同 K 完整成功加 1、最高 10，连续计数清零；HTTP 200、响应头或开始输出不算完整成功，中性取消不回血。 |
| R13 | 满分连续基础 1 失败，无回血，剩余分为 9、8、6、4、1、0，第 6 次归零；基础 2 时为 8、6、3、0。 |
| R14 | 已交付有效流式内容后，不透明重发或拼接另一模型输出；上游断流与客户端取消区分处理。 |
| R15 | 429/上游并发满也参与阶梯加重；冷却跳过没有真实调用，不额外计失败。 |
| R16 | 可信证据确认当前 K 余额耗尽/凭据不可用，直接归零进入可恢复熔断，不永久禁用。笼统 401/402/403、未经适配文本或中转内部线路余额不足不足以直接置零。 |
| R17 | 首次熔断 1 分钟后允许一个请求探测；探测失败间隔按 2、4、8 分钟翻倍且有上限；完整成功从 0 恢复到 1，后续成功 +1。确认充值/更新凭据可提前允许探测。 |
| R18 | 上游恢复与被网关发现可能有延迟；到期仅允许探测，不保证已恢复或准点后台调用。恢复资格不强制切回：人工模式仍按原顺序，缓存模式可继续稳定使用备用 K。 |
| R19 | 同一次请求在同一个 K 上的重试额外等待累计最多 2 秒；所需等待超预算就转下一候选。保留上游完整冷却期限，不把要求等待 30 秒改成 2 秒后强行调用。所有候选不可用时明确返回错误，不无限挂起。 |
| R20 | 流式聊天首输出前总预算可配置、默认 90 秒，从进入调度起跨 K/重试共享，计入选择、排队、连接、等输出与退避。正常有效输出后不被该预算截断；非流式、compact 保留各自完整响应超时；不取代 WS 整轮/连接时限或绕过续接限制。 |
| R21 | 聊天旧配置值 2 因 legacy 特判未生效的目标，迁移为两次总尝试；界面改为“总尝试次数（含首次）”，保留显式覆盖并显示生效次数。用户接受因此增加失败后的调用与等待，仍受健康、冷却和适用时间预算约束。 |
| R22 | 相同模型、同等能力与兼容条件的可用候选按 K 已配置价格倍率升序，仅同倍率优先复用。不让亲和压过更低倍率；不承诺最低实际账单。 |
| R23 | 必须绑定原 K 的有状态续接，仅在安全且允许时有限重试原 K；无法恢复明确返回错误，由持有完整上下文的客户端决定重建。网关不跨 K 转发旧引用，不擅自删除引用或拼装历史；普通可安全重试的独立请求照常故障转移。不保证客户端自动恢复。 |

## 本版技术选择

以下是落实已确认行为的设计默认值，随最终规划审阅；不是声称用户逐项批准过每个数值。

| 决策 | 本版选择与理由 |
|---|---|
| D1 错误分类 | 采用 R10/R16；先区分归因和当前 K 作用域，再决定健康及重试。分类细表见设计。 |
| D2 重试和迁移 | 以总尝试数为唯一执行契约，保留显式覆盖，修正旧 2 的语义；普通暂态失败首次等待 0.5-1 秒，后续指数退避，受 R19 累计上限约束。无等待提示的 429/上游并发满冷却从 1 秒翻倍至 60 秒；明确 Retry-After 不被该本地上限截短。 |
| D3 熔断恢复 | 新聊天策略移除旧固定 8 次预算、低成功率窗口的额外触发及旧快速满血恢复；成功率窗口保留诊断。归零统一熔断，半开失败重新冷却。探测间隔沿用现有配置上限，约束 1-32 分钟，旧 0 不允许变成忙循环。 |
| D4 亲和读写 | 暂态失败先保留绑定，冷却/归零时过滤；备用完整成功后迁移本会话绑定。失效解绑精确匹配 K 与作用域，不扩散至同 endpoint 其他 K；模式切换与并发完成不允许迟到结果覆盖较新的绑定。 |
| D5 协议边界 | R23 已确认；区分可重放、已提交有效内容及有状态绑定，保留现有格式适配与工具调用完整性约束。 |
| D6 超时 | R20 已确认；单次流式默认先保留 30 秒及现有有效覆盖配置，不统一压低非流式 300 秒/compact 1200 秒默认。90 秒不保证每个 K 都能试完。 |
| D7 状态兼容 | 旧归一化健康保留并换算显示，不将低健康直接重置为满分；旧失败预算不能当新严格连续次数，新计数从 0 开始并标版本。既有熔断/冷却保留恢复资格和截止时间。 |
| D8 性能与证据 | 复用现有仓储、锁/CAS、缓存及请求记录；准确扣分/回血优先于写入节流。模拟上游验证次数、顺序和后续读取，无需付费压测。 |

## 时间与事实边界

30 秒乘两次约 60 秒只是单 K 的两次超时算例，另有退避/排队；90 秒限制适用流式请求的跨候选累计等待。以前“4 分钟”和“固定 8 次连续失败”的说法不作为设计依据。45 秒预算、全请求最多 3 次尝试等早期建议不采用。

仓库的 HTTP 候选等待、传输首字节、WS 首事件、整轮完成和连接寿命不同，不能都叫“首字”。收到心跳或 response.created 不代表有模型有效输出；有效工具调用输出可构成进展。具体提交判据见设计。

没有上游延迟实测，不能宣称 30/90 秒最优；如果正常推理经常超过单次时限，应校准单次设置。客户端或前置代理可能提前超时。已确认根因也可能恢复，因此明确不可用仍有恢复路径。

## 验收条件

以下是实施验收目标，最新结果与证据边界见 [验证记录](research/verification-log.md)。

| 编号 | 需要观察到的结果 | 对应需求 |
|---|---|---|
| A1 | 三种模式经配置/API 进入真实调用链；固定顺序、缓存复用、低倍率优先及同倍率亲和分别成立；备用成功后的后续请求顺序正确。 | R1-R4、R18、R22 |
| A2 | 显式总尝试 2 时，K1 快速 500 两次后调用 K2；K1 可未归零，K2 成功不恢复 K1。迁移旧 2 同样生效，覆盖/继承、保存/刷新、重复迁移一致。 | R5-R6、R9、R21 |
| A3 | 轻失败序列 9、8、6、4、1、0，重失败序列 8、6、3、0；混合错误共享连续计数，完整成功 +1/清零，中性事件不更改计数。 | R9-R13、R15 |
| A4 | 已知本地拒绝不扣分；可信当前 K 余额/凭据错误直接零，不确定中转鉴权/内部线路报错不误用直接零；异常 200、连接/TLS、等待超时按类型处理。 | R7-R10、R16 |
| A5 | 429 短等待在累计 2 秒内再试；长等待转下一候选，原 K 完整冷却不被其他请求绕过；冷却跳过、未尝试目标均不扣分。 | R8、R15、R19 |
| A6 | 归零后排队候选也停止普通尝试；到期仅一个持有效租约的探测；成功恢复 1，失败延长冷却；旧凭据或旧熔断代次的迟到成功不能清除新故障。 | R16-R18 |
| A7 | 每个真实 attempt 仅一次健康结算；多实例重复报告、乱序完成、CAS 冲突不重复扣分或丢掉回血；状态存储异常可诊断、不伪造成功写入。 | R9-R12 |
| A8 | HTTP 同步、SSE、WS 分别验收；已交付文本/工具调用后断流不透明重发，取消不被记成上游超时；有状态续接失败不跨 K，独立请求仍可选择备用。 | R14、R23 |
| A9 | 90 秒预算不因重试/换 K 重置，耗尽不再发新尝试；正常有效输出后不被该预算截断；非流式/compact 原时限保留；心跳不冒充进展。 | R19-R20 |
| A10 | 管理端显示权威生效尝试数、真实调度健康与恢复状态；成功率与健康分不混用；状态刷新一致，错误详情脱敏且不泄露 K。 | R9、R17、R21 |
| A11 | 存量健康/配置迁移幂等，非聊天行为不被新策略改写；模式保存保留既有条件规则、请求修改和终止规则。 | R4、R7、R21 |
