# 修复设计

SQLite 的 list_dashboard_daily_breakdown_from_daily_aggregates 将所有每日总量写为 model/provider = aggregate，并把最大汇总日期之前的原始记录全部跳过。网关随后将这些占位行当作真实模型和供应商，所以图表及分组数量失真。

在数据读取层区分每日总量、已保存的模型供应商分组和实时请求分组。使用已有 stats_daily_model_provider / stats_user_daily_model_provider，在缺少分组的历史日期读取仍存在的原始记录；逐日决定覆盖关系，避免用最大日期跳过中间空洞。总量与维度分别组装，防止重复累计，真实名称不通过字符串黑名单过滤。

仓库内部类型明确标识总量与分组行；网关保持现有统计响应，并在历史明细确实缺失时提供明确的未归属指标，前端展示说明和未归属金额。不存在的历史明细不能根据总金额猜测分配。

修改范围为 SQLite usage 读取和测试、usage 数据契约及内存实现、仪表盘 API 组装和测试，以及必要的前端类型、图表提示与测试。无需修改数据库 Schema、持久化历史记录或结算逻辑。

## 最终实现

内部行类型以 Usage / Totals / Breakdown 区分累计用途。全部查询在同一读事务中执行；原始记录数量完整的 UTC 日使用原始记录并按请求时区分桶，原始记录已清理的历史日保留原聚合的 UTC 日期标签。不能从只有每日总量的数据猜测小时分布。覆盖检查细化到日期、模型和供应商，避免部分分组存在时忽略其他仍可恢复的原始分组。

API 每日返回 unattributed_requests / unattributed_cost。缺失明细的部分仍在总量中，并以单独灰色图例展示；真实模型和供应商的唯一数量只计算真实分组。前端不再删除模型名称前缀。
