# 模型映射批量表格工作台

## 请求、现状与关联

用户确认采用已预览的表格方案改造批量模型映射。当前 `BatchModelMappingDialog` 采用“先选客户端模型，再维护提供商模型”的两栏表单；编辑多个客户端时要反复切换，无法直接比较各模型的映射状态。

关联 `docs/specs/frontend/index.md` 的“模型查询和批量映射错误保留完整详情”“模型映射统一使用全部端点、全部请求与上游刷新”和“窗口自适应与滚动条”。本次不改长期业务规则；表格是既有批量映射职责内的呈现方式变化。

## 本次变化与决定

- 批量映射弹窗改为全客户端模型表格：客户端模型、提供商模型、状态、操作。
- 行内添加直接搜索或输入提供商模型；已映射名称可单独移除，也可整行清空。
- 支持搜索、全部/已映射/未映射筛选和“只看已修改”；筛选不改变草稿。
- “已隐藏”模型可单独查看并恢复；隐藏与显示只影响当前草稿是否显示，不删除映射，也不影响保存载荷。
- 保留刷新上游模型、首次缓存读取、手动强制刷新、完整错误详情、取消确认和逐个模型保存。
- 保存仍只更新发生变化的默认范围映射；旧的非默认范围项按原逻辑保留。
- 关联已有任务 `docs/tasks/10-25-model-mapping-scope-refresh/plan.md` 中尚未统一验证的契约；本轮不重跑无关映射入口。

## 预期效果与范围

用户在一个弹窗内查看并批量维护当前供应商的全部客户端模型，较少反复切换。窄窗口继续使用纵向卡片，不依赖横向滚动；内容较多时由弹窗正文区域纵向滚动，底部关闭与保存始终可达。

不包含：后端接口、映射数据结构、调度规则、单条映射弹窗、映射列表页和非默认范围兼容逻辑的改动。

## 验收与实际检查

- A1：打开弹窗即展示全部客户端模型；既有映射、未映射状态和数量正确。
- A2：搜索、状态筛选和“只看已修改”只改变可见集合，不改变草稿。
- A3：行内添加、删除名称和清空均立即更新该行状态与待保存统计；取消或恢复基线可撤销草稿。
- A4：保存只提交变化的模型；部分失败保留失败草稿和完整原因，全部成功后关闭。
- A5：刷新上游模型继续使用首次缓存与手动强制刷新；失败保留旧列表和草稿。
- A6：900x640 与 1200x820 下无页面/表格横向溢出，保存和关闭按钮可达；浅深主题可读。
- A7：隐藏/显示模型只影响可见列表，不丢失草稿，不改变保存目标。

## 审查后修正

独立审查发现三项必修问题，均已处理：

- 供应商详情原先直接读取默认 100 条模型，超过 100 个客户端模型时工作台不完整。现新增 `getAllProviderModels`，按后端单页上限 500 条连续读取；原 `getProviderModels` 的单页契约保持不变。
- 最后一行/最后一张卡片候选下拉可能被表格或卡片的 `overflow-hidden` 裁切。现将候选浮层改为 Radix Portal，以输入框为锚点并抬高到弹窗之上；表格与窄屏卡片末尾均已实点验证。
- 新增命名类型、组件和辅助函数补齐中文职责及约束注释。

同时补充了非默认范围映射保存载荷断言，确认批量保存只替换默认范围，历史端点范围项原样保留。

第二次独立审查发现工作台新增文案缺少英文映射，已补齐：

- 状态筛选、已映射/未映射/已修改、隐藏恢复、待保存统计、添加入口、空态和无障碍名称进入现有 legacy i18n 精确/动态字典。
- 英文单复数按实际数量展示，例如 `1 pending change`、`2 pending changes`。
- `i18n.spec.ts` 覆盖工作台状态、操作和动态统计；fixture 支持 `?locale=en`，真实浏览器检查英文筛选、添加、待保存统计、保存按钮可用和恢复基线。
