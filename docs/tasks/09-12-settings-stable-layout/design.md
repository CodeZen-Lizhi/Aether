# 系统设置设计

## 设计结论

使用一个常用设置主页和两个同框架二级页面（代理管理、高级设置）。尺寸变化只影响弹性留白，不增加或减少列，不将分类导航改成下拉框。原四分类是上一轮结果，本方案替代其信息架构，不撤销已实现的分组保存和数据保护。

## 首页结构

```text
系统设置                                     高级设置 >

网关
-------------------------------------------------------
出站代理                        [ 当前代理 v ]  [管理图标]
未单独指定代理的请求使用此设置。

网关端口                                   [ 8084     ]
保存后重启网关。

开机启动                                          [开关]
登录 Mac 时启动 Aether 和网关。

数据备份
-------------------------------------------------------
备份与恢复                     [创建备份]  [恢复备份]
配置、API Keys 与用量统计等。

Aether 实际版本
```

- 主标题只出现一次；不再显示「连接与启动 / 默认出站代理 / 默认代理」三级重复标题。
- 代理右侧管理用 Lucide `SlidersHorizontal` 图标，提示「管理代理节点」；进入同框架代理列表页，复用原节点编辑弹窗，避免弹窗套弹窗。
- 出站代理保留当前保存流程，修改后出现局部取消/保存。新增、删除当前节点与返回后的选择状态仍由现有 store 和回调协调。
- 端口 8084 只是示例，实际绑定 status.port。显示输入框，编辑后出现「取消 / 保存并重启」，保留校验、禁用及重启状态；使用桌面现有命令，不伪装为普通 HTTP 设置保存。
- 开机启动沿用即时保存；请求中禁用，失败反馈且显示实际状态。
- 创建备份和恢复备份视觉并列，用图标加文字的轮廓按钮；蓝色实底留给编辑后的保存确认，避免无编辑时备份按钮成为过强视觉焦点。
- 备份范围短描述准确但不列全字段；恢复预览仍展示完整范围。不得把现有 aggregate 格式称为整个数据目录镜像。
- 页尾版本低强调，不放大状态卡片。网关状态和启停仍由 APP 顶部承担。

## 固定结构与空间预算

以原生逻辑尺寸规划，不能用截图物理像素推断 CSS 字号。900px 最小宽度减 128px 全局侧栏和约 32px 外边距，可用正文宽度约 740px；实施时以真实 DOM 测量为准。

| 项目 | 最小窗口 | 大窗口 | 约束 |
| --- | --- | --- | --- |
| 设置内容 | 填满可用正文宽 | 最大 960px，居中 | 标题、组和页尾共享对齐轴 |
| 页内二级侧栏 | 无 | 无 | 全局 APP 侧栏沿用现状 |
| 设置行 | 左标签、右控件 | 左标签、右控件 | `minmax(0, 1fr) minmax(280px, 320px)`；英文备份按钮保持单行 |
| 行两列间距 | 16px | 最多 32px | 内容宽度驱动平滑变化 |
| 行上下留白 | 12px | 最多 20px | 不用拉高空行填满屏幕 |
| 分组间距 | 24px | 最多 40px | 不改变分组顺序 |
| 标题 / 标签 / 辅助文字 | 24 / 13-14 / 12px | 相同 | 禁止 viewport 字号或 CSS zoom |
| 输入与按钮 | 36-38px 高 | 相同 | 图标 16px，圆角 6px |

布局从最小尺寸起设计；大屏只扩展到最大内容宽度，剩余空间留在两侧。公共 AppShell 已有 padding，不重复叠加大内边距。首页正常态正文高度目标不超过约 500px（不含全局 header），以最小窗口首屏可达验收反推实际间距。

缩放不改变网关行、备份行的列关系；文本可以自然换行，输入、按钮不得重叠。异步错误、英文长文本或主动展开允许纵向变高，这不等于切换布局。390px Web 检查仍保留既有兼容要求，但不得作为 APP 最小窗口依据。

## 视觉规范

- 颜色使用已有语义 token，不新建主题。明亮参考：background #ffffff、foreground #0f172a、muted-foreground #64748b、primary #2563eb、border #e5eefc；暗色直接消费现有主题变量。
- 页标题保留 `TiemposText` / 现有衬线 fallback，与全局页头一致；设置区域分组、字段统一现有 `--sans-serif`，不在细小标题上混用衬线。页内字距统一 0。
- 只用结构性分隔线；分组不放浮动卡片、投影或大圆角容器；不引入装饰媒体、插图或背景动效。视觉资产沿用 Lucide 功能图标。
- 控件 hover、focus 和保存反馈沿用组件体系；导航变化不做延迟可用性的入场动画；无自动播放装饰。

## 高级与代理管理

两个二级页面与首页同宽、同标题基线，提供带左箭头的返回入口。高级页面默认六个简洁折叠分组：记录与清理、请求兼容、密钥规则、配置迁移、诊断、数据维护。折叠由用户控制，窗口缩放不能改变 open 状态。仍可同时保留多个分组草稿。

「记录与清理」沿用原两组保存边界、真实保留期口径和自动清理开关；「请求兼容」「密钥规则」在视觉拆分时仍共享 basic 保存边界，不能制造两个互相覆盖的提交范围。清空操作只在数据维护内部用危险色。

代理管理复用当前节点列表、测试状态和编辑弹窗；列表默认不再占首页空间。离线已选节点不得被新布局静默切换为直连。无节点时仍能选择直连并从管理入口添加。

## 技术边界

- `SystemSettings.vue` 负责 homepage/proxies/advanced 视图编排，继续复用 `useSystemConfig` 快照与保存方法。已访问视图保留挂载和草稿。
- 拟保留 query 键 `tab`：`general` 默认、`proxies`、`advanced`；兼容 `connection -> general`、`records -> advanced/记录与清理`、`backup -> general/数据备份`，原 advanced 不变。旧 hash 优先定位具体分组并自动打开必要折叠层。
- `ProxyConfigSection.vue` 按 selector/management 使用场景拆清展示职责，不重复挂载节点编辑弹窗；共享 store、测试格式化及默认代理删除回调。
- `DesktopSettings.vue` 调整 connection 展示，保持 recovery 路径及诊断行为；必要时新增仅用于布局的 props，避免修改 IPC 与生命周期。
- `DataManagementSection.vue` 将完整备份常用操作与配置迁移拆成可单独编排的展示片段；保留原 file input、加载状态、预览及恢复弹窗所有权，不能同时挂载两个重复导入入口。
- `settings.css` 替换分类导航的 760px 模式切换；样式限于设置页，避免更改全局标题、侧栏和其他业务列表。
- `messages.ts` 添加新文案映射；前端 spec 在实现验收后更新旧四分类约定。

## 风险与验证边界

设计示意只验证信息层级的可讨论性，不证明真实 APP 在最小尺寸下通过验收。实施后必须用真实 AppShell、真实字体、实际显示器最大化和连续拖动测试；不能用截图缩小模拟布局。

端口重启、真实恢复和清空不在规划期执行。实施验收使用隔离状态、fixture 或可丢弃实例验证写操作；原生最大化/字体/IPC 若运行条件不足应明确未验证，不能用 Web 测试冒充。

回滚只恢复本次前端编排、样式和文案，无数据迁移、默认值或后端回滚。保留用户并行改动。
