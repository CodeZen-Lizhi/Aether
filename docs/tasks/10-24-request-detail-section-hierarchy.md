# 请求详情执行路径横向链路重构

## 请求与关联

用户先选择纵向瀑布，随后以项目内真实组件原型重新确认请求入口、供应商/Key 与请求结果的横向链路，并要求正式替换。目标是只画真实走过的上游调用，在同一路径中区分供应商与其 Key，展开某个 Key 后再看该次调用的真实错误与上游响应。

关联长期 Spec：[前端规范](../specs/frontend/index.md) 的“窗口自适应与滚动条”和“请求详情首屏与尝试分页”。本次将执行记录从纵向瀑布更新为横向请求链路，并将窄屏路径内部横向滚动登记为独立例外；计费明细、请求上下文、更多数据及请求上下文中的调用密钥/上游执行 Key 语义保持不变。

## 本次结果

- `HorizontalRequestTimeline.vue` 使用横向请求路径：请求入口和请求结果均为带语义边框与背景的圆角卡片，入口两行显示 `POST` 与真实路径；实际发出的供应商按调度顺序横排，同一供应商的 Key 在框内纵向排列；供应商重访保留独立调度节点，并使用独立节点身份避免重排复用，无障碍摘要按唯一供应商计数；请求结果标题与状态码同一行、状态码靠右，总耗时另起一行。
- 只展示真实发出调用，未尝试、未使用和 `key_circuit_open` 等冷却跳过不进入路径；没有真实调用时显示“没有已发送的上游请求”。
- 路径画布增加 18px 间距的浅色点阵背景，深色主题单独调整点阵对比度；每张供应商分组按身份使用六组低饱和身份色之一，同一供应商重访沿用原色调，底色不承载成功或失败语义。供应商使用 2px 深色虚线分组，标题只显示序号和名称；换 Key 使用红色纵向箭头，供应商之间使用横向箭头。请求入口到首个供应商、供应商之间以及末个供应商到请求结果的连接线均覆盖完整间隔、紧贴边框、垂直居中，且不承载“路由”或状态码文字。组件颜色直接使用项目完整色值变量，避免 `hsl(var(--...))` 导致卡片边框和背景失效。
- Key 卡片固定 88px 高，显示真实 HTTP、Key 名称、耗时和单行简短原因；成功状态不生成原因文字，避免与符号、状态码和读屏结果重复。超长失败原因单行省略，并通过 `title` 和展开控件的可访问名称保留全文，不撑高卡片或供应商框。成功使用 `#15803d` 语义绿色、失败使用 `#dc2626` 正红、进行中使用蓝色。
- Key 详情默认收起；点击后在整条路径下方展开，再次点击收起。刷新或重排按记录 ID 保持展开身份，新请求使旧展开状态失效。详情保留 HTTP、耗时、时间、可选凭据、usage/图片进度及真实上游错误，不重复供应商名或 Key 名。
- 多供应商始终横排；390px 等窄屏只让路径容器内部横向滚动，不切换为纵向卡片或下拉列表。页面和抽屉本身仍不得横向溢出。
