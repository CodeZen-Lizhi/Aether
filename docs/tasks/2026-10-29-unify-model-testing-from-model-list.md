# 模型测试统一收敛到模型列表

日期：2026-10-29

## 目标

- 模型测试只从供应商详情的模型列表进入；模型映射页不再提供测试按钮、测试状态或测试弹窗。
- 测试弹窗使用“测试 Key（左）/ 模型映射（右）”两个单选，默认均为“自动”。
- 自动模式按映射优先级及现有 Key 排序生成“映射 × Key”候选，成功即停；成功后的剩余候选显示“未使用”。
- 请求头、请求体默认收起并按需展开。

## 边界

- 有映射时“自动”仅测试映射；没有映射时才回退请求模型直连。
- Key 必须兼容当前端点，并允许请求模型或对应映射模型；无权限组合不进入候选。
- 不新增测试工作台、批量测试模式、数据库表或迁移。
- 保留映射编辑、批量映射、刷新、正则映射展示。

## 验收

- 四种选择组合分别生成完整、按映射收窄、按 Key 收窄和唯一组合。
- 候选按映射优先级、Key 熔断/健康/连续失败顺序执行，成功即停。
- 结果表按“顺序、Key、模型、状态、耗时、详情”展示并包含未使用候选。
- 映射页不存在测试入口。
- TypeScript 类型检查、目标 Vitest、网关目标测试、前端构建和真实浏览器检查通过。

## 实施结果

- 前端目标测试 82 项通过，`type-check`、ESLint 和生产构建通过。
- 网关 `cargo check`、格式检查及 15 项目标测试通过。
- 真实组件浏览器验收通过：1200 / 900 / 390 宽度下无横向溢出，自动默认、请求区收起展开、结果列、未使用候选和详情展开符合契约。
