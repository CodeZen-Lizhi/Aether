# 弹窗尺寸设计（待审阅）

## 尺寸契约

桌面沿用现有 size / maxWidth API 和优先级，内部统一映射比例和上限。宽度为 min(当前视口宽度 × 比例, 档位上限)，并受可用边距约束。禁止使用 screen.width 或在 mounted 时缓存窗口尺寸。

| 档位 | 窗口宽度比例 | 最大宽度 | 主要用途 |
| --- | --- | --- | --- |
| sm | 40% | 384px | 紧凑提示 |
| md | 46% | 448px | 默认确认、认证、导入 |
| lg | 52% | 512px | 映射、别名、规则 |
| xl | 58% | 640px | 供应商、Key、供应商模型表单 |
| 2xl | 66% | 768px | 端点管理、模型权限、批量选择 |
| 3xl | 74% | 880px | 全局模型、模型测试 |
| 4xl | 78% | 960px | 兼容保留档位 |
| 5xl | 82% | 1024px | 批量映射 |
| 6xl | 82% | 1120px | 图片预览、请求回放 |
| 7xl | 82% | 1120px | 兼容保留档位 |

上限是设计值，实施时用 rem 表示（表中以默认 16px 根字号换算）。全档总高度 max-height: min(80dvh, 50rem)。底部抽屉仍在小于 640px 下使用原移动规则。桌面 640-839px 是兼容区域，可给档位一个最多 360px 的可读宽度下限，但始终受 82vw 和安全边距限制；900px 及以上严格使用表中比例。不得用固定最小高度撑开短内容。

主要尺寸例子（宽度，px）：

| 内容窗口 | 供应商 xl | 模型测试 3xl | 图片/回放 6xl | 总高上限 |
| --- | --- | --- | --- | --- |
| 900×640 | 522 | 666 | 738 | 512 |
| 1200×820 | 640 | 880 | 984 | 656 |
| 1440×900 | 640 | 880 | 1120 | 720 |
| 1920×1080 | 640 | 880 | 1120 | 800 |

比例是针对本项目内容密度的建议，不声称是某一操作系统强制标准。取舍是小窗口长表单需要更多纵向滚动，但可获得明确的背景留白。

## 实现边界

- 优先在共享 Dialog 内以 CSS 控制响应式宽高，保留现有 props、emits、Teleport、遮罩、ESC 和层级契约。
- 为 Dialog 与独立 ReplayDialog 提供同一可复用尺寸样式/token；不为统一尺寸强迫重写回放的交互结构。
- header/footer 不收缩，body 使用 min-height:0 / min-width:0。避免 body 与业务根节点同时按视口设置高度而形成多重滚动；列表、编辑器等确有独立滚动语义的区域可保留。
- 不对 width/height 使用 transition-all，避免窗口拖动时弹窗尺寸滞后；保留透明度/位移开关动画。
- 在实际内容宽度不足时重排字段和左右面板，采用现有容器布局模式或局部容器查询。尤其检查 BatchModelMappingDialog 的 lg 两栏及 20rem 下限、GlobalModelFormDialog 的独立高度、ModelTestDialog 的图片和代码、ReplayDialog 的固定半宽布局。
- 图片 object-fit:contain，最大高度服从 body 可用高度，不能将 72vh 图片叠加 header/footer 后超过总高预算。
- 只修复与尺寸收紧直接相关的字段布局；业务请求、事件回调、表单值和测试状态不变。

## 兼容与风险

- 同一前端服务桌面 WebView 和普通浏览器，共享组件改变会同时影响两者；保留移动端形态。
- 640-839px 及英文长标签更易挤压，需要测量实际字段，不以 CSS 类名检查代替布局验收。
- 浏览器模拟接口只能证明布局与状态展示；真实外部模型执行与原生 WebView 渲染要单独标识验证来源。
- 工作区存在预先修改的桌面依赖、Cargo 锁文件和 tauri 配置及 output/；实施不得覆盖或纳入本任务提交。
