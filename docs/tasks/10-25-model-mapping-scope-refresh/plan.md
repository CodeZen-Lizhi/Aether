# 移除模型映射范围选择并修复单条刷新

## 请求、现状与关联

编辑供应商模型映射时，默认的全部请求、全部端点信息重复出现；批量映射还有独立默认范围说明。单条编辑的刷新没有获得上游新模型，批量映射刷新正常。用户随后明确：当前所有实际映射均使用全部端点、全部请求，前端不应再支持或展示其他范围。

关联 `docs/specs/frontend/index.md` 的“模型映射统一使用全部端点、全部请求与上游刷新”和“模型查询和批量映射错误保留完整详情”。本次由用户确认范围规则变化及手动刷新语义。

## 本次变化与决定

- 旧规则：单条编辑保留端点和请求范围选择，非默认范围在列表展示并可编辑。
- 新规则：单条编辑、批量映射和列表均移除适用端点、适用请求及范围徽标；界面不再出现会话压缩请求范围。
- 前端保存映射只写 `{ name, priority: 1 }`，省略 `endpoint_ids` 和 `operations`，由未改动的后端默认解释为全部端点、全部请求。
- 编辑、分组和删除按当前可见的模型、名称处理，不再以隐藏的端点或请求范围区分。
- 首次加载允许缓存，两个弹窗的手动刷新均强制跳过缓存；成功空响应替换旧模型，失败保留旧列表与草稿。
- 确认依据：用户明确要求“无论在编辑模型、编辑模型映射、批量模型映射，还是映射列表上，都不要展示适用范围”，本轮按要求不运行测试。
- 工作区已有倍率、任务文档和未跟踪资源改动均不属于本任务，不修改或纳入验收。

## 预期效果与范围

用户在模型映射列表、单条编辑和批量映射中都看不到端点或请求范围。点击单条编辑的刷新后，实际请求跳过后端缓存，成功响应中的新模型出现在当前列表，已有选择和错误处理保持原行为。后端契约、调度规则和存储结构不改变。

风险分级：Standard。H1-H5 均否；目标和直接调用方明确，但同次修改多个可观察入口，L2 不满足。无跨层接口变化，不触发 APP 原生或安装验收。

## 验收与实际检查

- A1：列表、单条编辑和批量界面都不展示端点/请求范围控件或范围徽标；测试断言已同步，待用户统一测试。
- A2：编辑保存载荷只含 `name` 和 `priority`，不含 `endpoint_ids`、`operations`；测试断言已同步，待用户统一测试。
- A3：首次打开使用缓存，手动刷新强制请求并显示最新模型；上一轮的组件与浏览器证据仅覆盖旧方案，新版本未测试。
- A4：真实浏览器布局与操作可达性；本轮按用户要求未执行，待统一测试。

已做静态自检：相关组件不再引用范围选择、范围标签或 `MultiSelect`；`git diff --check` 无输出。现有 fixtures 已改成全范围示例，未启动预览。用户明确要求本轮先只改代码、后续统一测试，因此未运行组件测试、类型检查、浏览器验收或完整门禁。
