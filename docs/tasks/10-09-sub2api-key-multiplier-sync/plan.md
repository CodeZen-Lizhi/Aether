# SUB2API 密钥倍率同步

日期：2026-10-09
状态：首版已交付桌面 0.1.41；正在扩展 New API 与 API Key 倍率查询并调整逐密钥界面。

## 目标与范围

为本地供应商密钥提供「手动倍率」和「跟随上游」两种模式。跟随上游时，复用 SUB2API 账号认证，在余额刷新周期中同步实际生效的分组倍率，并支持供应商级和单密钥立即同步。

首版支持 SUB2API，本次扩展 New API 与 API Key 模板。只匹配 Aether 已配置的密钥，不自动导入上游密钥，不修改上游配置，不因上游删除、禁用或未匹配而删除本地密钥。

## 已确认需求

1. 现有密钥和新建密钥默认使用手动模式，保持原有成本倍率。
2. 手动模式可编辑成本倍率，余额刷新和倍率同步均不得覆盖该值。
3. 跟随上游模式显示当前生效倍率、上游分组、最后成功同步时间和最近尝试结果；倍率输入不可直接编辑。
4. 切换到跟随上游后发起同步；首次同步成功前保留当前倍率，明确显示尚未同步或失败，不能声称已跟随成功。
5. 切回手动模式时保留当前生效倍率，之后允许手动修改。
6. 定时与手动余额刷新均触发倍率同步，共用现有余额刷新周期，不新增独立定时任务。只有存在跟随上游密钥时才查询倍率相关接口。
7. 界面仅在单密钥提供立即同步操作；供应商级同步接口继续用于后台刷新。
8. 手动模式下的单密钥同步操作不可写入，并提示先切换模式；供应商级同步跳过手动密钥。
9. 上游未配置到本地的密钥完全忽略。例如上游有三个、本地有一个，只处理本地这一个。

定时同步属于周期刷新，不是实时推送；上游变化在下一次成功刷新或立即同步后生效。余额与倍率属于同一轮刷新，分别报告成功、失败和完成时间，不强制具有相同成功时间。

## 匹配和更新契约

- 在同一供应商对应的站点和账号内，按完整密钥精确匹配；不得按名称或密钥末尾匹配。分页必须遍历完整，避免漏匹配。
- 生效倍率为用户专属分组倍率（存在时），否则为分组默认倍率；二者不相乘。数值 `0` 是有效值，不能用真假判断代替存在性判断。
- 返回倍率必须有限、非负，符合本地持久化契约。上游值超出当前 UI 可表达范围时不得截断或静默改成 `1`，实施时核对并明确兼容策略。
- 成功后更新现有唯一生效字段 `default_rate_multiplier`，计费和成本排序继续读取它；不得恢复旧的按协议倍率覆盖字段。
- 未匹配、无有效分组、接口不支持、鉴权失败、超时、解析失败或倍率非法时，保留上次生效倍率和成功时间，记录最近尝试失败原因。
- 余额与倍率步骤独立报告结果；共享认证失败时两者分别报告失败。一个子步骤失败不能清空另一个的成功数据。
- 写入前重新校验密钥仍属于目标供应商、密钥值未变、模式仍为跟随上游。用户切回手动模式后，进行中的同步不能覆盖手动值。
- 同一供应商的同步须串行化或采用版本校验，防止旧请求结果覆盖较新结果；单密钥与供应商同步也遵循该规则。
- 上游密钥列表仅用于本次匹配，不额外落库完整密钥；日志仅使用本地 ID 或安全指纹。

## 状态与界面

所有供应商密钥显示模式选择控件和当前倍率。手动支持编辑；跟随上游显示只读倍率和同步信息。New API/API Key 切换前查询验证能力，失败保持手动并提示原因；auto 动态分组拒绝开启。

同步结果区分：已同步、未同步、未匹配、无有效分组、接口不支持、同步失败。上次成功时间和最近尝试时间分别记录，失败后不可用旧时间表示本次成功。

供应商操作返回匹配、更新、未变化、未匹配、失败和跳过数量；支持部分成功，空集合明确提示无待同步密钥。单密钥操作显示具体结果。加载期间阻止重复点击。

持久化所需语义：倍率来源、当前生效倍率、上游分组信息、最后成功时间、最近尝试时间及状态/错误。具体字段和 API 结构沿用项目模型确定，不在需求阶段锁定冗余字段。
