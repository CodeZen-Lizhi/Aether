## 1. 背景与目标

本模块实施前，Vela 只有桌面壳与类型化绑定，尚无正式模型管理和数据库业务。已有 Svelte 原型展示模型、价格和测试，但使用合成目录，不能证明真实目录导入、持久化或计费已经实现。

模型管理用于维护统一模型身份、展示信息与标准价格规则，供后续供应商关联、映射、执行和费用记录引用。在线目录减少手工录入，本地编辑用于纠正或补充来源数据，同步不能覆盖用户已修改的规则。

用户已重新确认：继续使用 models.dev 作为初始化及参考价格来源，记录来源供应商与同步时间，不承诺等于中转站实际扣款；保留本地价格编辑用于纠正滞后和补充缺项，站点专属差异不写入统一标准价。

期望第一阶段形成独立闭环：真实目录选取模型 → 加入本地模型清单 → 查看完整价格 → 编辑价格与分时规则 → 保存并重启重读 → 同步新来源，验证本地修改被保留、未修改内容更新。

## 2. 术语与模块范围

| 术语 | 含义 |
| --- | --- |
| 目录数据源 | 提供模型资料与价格的外部数据库，现有基线为 models.dev，不承接模型推理请求 |
| 目录供应商 | models.dev 内某条价格所属的服务提供方，不自动等同于 Vela 中用户配置的中转站 |
| 统一模型 | Vela 本地管理、对外使用和被映射引用的模型身份 |
| 来源价格 | 从目录读取的价格及规则 |
| 本地有效价格 | 来源初始化后，叠加已保存本地修改所形成的有效规则 |
| 上游供应商 / Key | 实际调用的中转站及凭据；其倍率、权限、健康和调度属于供应商相关模块 |
| 历史价格快照 | 请求开始时固定的价格规则，后续改价与同步不回算该请求 |

### 2.1 第一阶段交付

包含统一模型列表、搜索及类型筛选、目录搜索添加、价格详情、本地价格编辑、按规则组恢复来源值、全量价格同步、持久化与重启重读。覆盖第 3 节规则及验收 MM-A01～MM-A07、MM-A12 中适用部分；同步与恢复的主要异常处理已确认；完整价格编辑仍需收口第 7 节中确实影响常用场景的规则。

第一阶段核心闭环不依赖真实网关。2026-11-12 根据实际使用要求，Vela 已增量接入只监听本机的 OpenAI Chat 网关，模型页当前全部对话模型可在 Aether 中关联并真实调用；这不代表 Responses、Anthropic、Gemini、WebSocket 或媒体执行路径已完成。删除未关联模型可在第一阶段验证，有关联模型的删除必须保留第 3.6 节约束。

### 2.2 完整模块及后续集成

- 统一模型参与网关公开清单，供应商模型关联、Key 权限和映射引用该身份。
- 请求执行时按模型类型使用价格规则，并在开始时固定价格快照。
- 图片、视频、Embedding、Rerank 的真实测试、异步任务、用量与历史费用通过执行及诊断模块组合验收。
- 配置导入导出包含模型与映射，按总方案 R45 确定跨机搬运边界。

上述功能仍属整体目标，分阶段不代表取消。供应商管理、健康度、调度和模型验证不在本模块内重复设计。

### 2.3 已确定的精简边界

不自建需要人工维护发布的在线模型目录；不提供模型启停或额外授权开关；不提供单行同步；不在统一模型价格中保存某个站点的专属折扣。不纳入 Flex/Batch 和未经确认的 reasoning-effort 倍率。

优先保证常用流程好用、实现简单。首期不为冷门场景额外增加配置、预检查、状态或操作流程；遇到缺少来源等情况，在实际操作时用明确错误反馈处理。必要的数据保留、规则完整性及已确认功能仍需保证。普通加载、提示文案等常规实现选择由开发确定，不逐项设为需求确认关口。

## 3. 有效需求规则

以下继承已有确认，除明确标注的待确认边界外可作为需求依据；不表示已实现。

### 3.1 MM-R01：模型列表与详情

- 展示模型 ID、显示名称、系列、类型、能力、上下文及价格，支持名称/ID 搜索和对话、图片、视频、向量类型筛选。
- 列表以基础价和阶梯、Fast、峰谷、图片、仅输入等短标签表达概况，完整价格规则放入详情弹窗。
- 模型页不增加独立汇总卡片、可用上游数量、上下游关系或供应商跳转。
- 详情只读，详情与编辑弹窗不叠层；行内可发起编辑或删除。详情不重复展示执行接口。
- 已允许编辑显示名称及价格。模型 ID、类型、能力和上下文等元数据的额外编辑权限，尚未确认。

### 3.2 MM-R02：从在线目录添加

- 使用 models.dev 作为模型资料初始化及参考价格来源；不要求用户维护和发布另一套在线目录。记录来源供应商及最近成功同步时间供核对，不承诺目录价格等于中转站实际扣款。
- 2026-11-11 用户确认落实两步新增流程：顶部整行搜索与类型筛选，下方厂商条，再下方双列模型卡片。点击卡片进入确认表单，身份与元数据只读，名称和本地价格可编辑。目录页不提供创建按钮，最终表单统一使用“创建模型”，确认前不写入。
- 2026-11-11 用户修订入口与目录布局：模型页工具栏并列提供“在线添加”和“手动创建”两个入口，在线目录内不再放手动填写按钮。厂商条只列热门官方厂商（中美主流大模型厂商），不列中转与聚合来源；未列出的来源仍可通过搜索选到。搜索与厂商条固定不动，只有模型卡片区随滚轮滚动，弹窗内不显示滚动条。弹窗尺寸须与应用窗口匹配，不遮挡到窗口边缘。
- “手动创建”直接打开创建表单，不加载在线目录。手动创建必填显示名称、真实模型 ID 和类型；价格可留空并显示未知，能力和上下文未填写时保持未知。手动模型标记为“手动创建”，不自动关联同名目录、不参加来源同步。
- 返回目录或取消不保存草稿；失败保留表单并显示原因。同一模型允许再次选择，最终创建时提示“该模型已添加”，不覆盖原配置。在线确认时的本地改价按规则组保护，真实来源价格独立保存。
- 目录下载跟随全局代理，开启时使用全局代理，关闭时直连，不提供模型页独立网络配置。
- 第三方没有提供的字段保持未知，不补成零、不伪造支持能力；已知零价格与未知价格不得混淆。
- 同模型多供应商条目优先使用对应官方供应商价格；无官方条目时明确提示，由用户选择其他来源，不自动取第三方同名模型价格。重复添加等常规交互由开发沿用本地模型身份处理，不额外引入复杂的别名合并机制。

### 3.3 MM-R03：本地价格编辑与保存

- 目录数据仅初始化本地配置，用户可编辑价格和计费规则，补充来源没有提供的峰谷规则。
- 保存后重新打开及重启应用，仍读取已保存的本地有效规则；取消编辑不提交草稿。
- 来源值、本地修改及有效规则必须能在业务上区分，具体存储结构由实施确定。
- 用户已确认保留本地价格编辑，主要用于纠正来源滞后及补充缺项；站点专属差异不写入统一标准价。

### 3.4 MM-R04：全量同步与修改保护

- 通过顶部“同步全部价格”更新已添加模型的来源价格，不增加行级同步。
- 已修改的部分保留本地值，未修改的部分继续跟随来源更新；基础价格与峰谷规则分别保护，不因修改峰谷就冻结整个模型。
- 上下文阶梯等相互依赖的规则整体保护，不能混入新版来源的部分阶梯形成另一套规则。
- 提供“恢复来源值”操作，按价格规则组恢复；例如仅恢复基础价格时保留本地峰谷规则，恢复的部分重新跟随来源同步。上下文阶梯等关联规则须整体恢复。
- 来源下架模型时保留本地模型及已有配置，不自动删除；缺失来源字段保留已有值，不改成零，也不宣称该部分已取得最新来源值。
- 全量同步允许按模型部分成功：有效模型正常更新，失败模型保留原配置，结果说明成功、失败及原因。同一模型内相互依赖的规则整体校验，不写入半套阶梯；整个目录下载或解析失败时本次不更新。
- “恢复来源值”入口保持可点击，不为来源缺失增加禁用或预检查流程。执行时有可用来源值则恢复；没有时提示“没有可用的来源值”，保留本地配置。这里的来源指目录价格来源，不是调用模型的中转站。
- 本地改价或同步不能回算已开始请求的历史价格快照。

### 3.5 MM-R05：价格维度与规则

| 类型 / 规则 | 应保存和表达的内容 |
| --- | --- |
| 对话 | 文本输入、输出、缓存读取、5 分钟及 1 小时缓存创建；上下文阶梯可覆盖各档价格 |
| Fast 模式 | priority、fast 等处理模式可用相对 Standard 倍率或完整显式阶梯表达；与思考强度区分 |
| 图片 | 文本输入 Token、图片输入/输出 Token、美元/张默认价、尺寸 × 质量矩阵；有明确像素区间时用于矩阵未命中回退，不能把 Token 价与每张价混为同一字段 |
| 视频 | 基准每秒价、分辨率 × 每秒矩阵；来源未声明分辨率价时才使用基准价 |
| 向量 | Embedding、Rerank 等按类型表达输入 Token 或按次价格，不生成无意义的输出 Token 价；多模态拆价仅在来源明确提供时导入 |
| 峰谷 / 分时 | IANA 时区、工作日限制、左闭右开时段、倍率和可选节假日日历；基准价时段必须明确，不假定所有来源都提供低谷价 |

- 价格维度不足不代表可以猜测补齐；本地补充必须由用户明确配置。
- 分时规则使用通用规则，不在计费逻辑中按模型或供应商名称硬编码。
- 生效顺序为完整输入量选择上下文档位 → Fast 倍率或显式价格 → 请求开始时刻的分时倍率。
- 时区合法性、重叠窗口拒绝及完整价格组合需验证。舍入精度、阶梯边界、跨午夜规则和节假日日历来源见 MM-Q07。
- 供应商/Key 倍率留在对应资源配置；独立站点定价覆盖尚未确认，不能用修改统一标准价代替。

### 3.6 MM-R06：删除、身份与关联边界

- 删除从行内发起，需二次确认；取消不改变数据。
- 删除统一模型时清理对应供应商关联与 Key 映射，Key 权限和检测计划等关联范围须在集成时核对，不允许留下继续调用的无效引用。
- 历史记录保留，按总方案 R20：改名显示当前名称，删除保留最后名称与删除标记，同名重建不得合并历史身份。
- 删除涉及多个关联时的完整清理集合及失败一致性待 MM-Q06 收口，不能用删除孤立模型通过代替关联删除验收。

### 3.7 MM-R07：公开、测试与价格快照的集成契约

- 加入统一模型清单即进入公开模型范围，不再设置模型级启停或额外授权；实际调用仍须有匹配且可用的上游资源，不承诺“目录存在即可调用成功”。
- 模型映射仍在供应商内配置，统一模型管理不替代上游候选选择或健康判定。
- 按本地价格规则计算的金额明确标为“估算费用”，用于用量成本比较与统计；中转站实际扣款以其账单为准，不表达为已对账金额。
- 请求开始时固定目录/本地规则版本、命中档位、模式、时区规则和倍率等价格快照；不能使用完成时最新价格重算该请求。
- 图片、视频、向量的测试使用对应输入和执行路径；视频异步任务不能伪装成同步聊天结果。真实测试及费用归属由后续链路验收。
- 2026-11-12 的增量实现只覆盖 OpenAI Chat Completions；公开清单与真实调用通过不代表第 3.7 节其他类型、其他协议或完整计费快照均已验收，具体证据和边界见第 8 节。

## 4. 期望效果与界面反馈

正常流程中，用户可以看清模型身份、价格单位和已知规则，在详情中查看完整结构，并通过编辑与同步维护本地配置。

已确认：未知字段不伪装为零；删除有取消及确认；详情与编辑不叠层；配置可重读。同步结果说明成功、失败及原因；没有来源值时点击恢复直接报错并保留配置。其余加载、无搜索结果和保存错误反馈等按常规交互实现，不作为逐项产品确认的阻塞；成功结果仍以实际保存和重读为准。
